# 语义分析实践需求提取（仅完成选做3.3）
## 一、核心前提与不可修改的基础约束
> 要点：**仅修改结构体类型等价规则（假设5），其余所有基础假设、功能要求严格保持不变，禁止实现选做1、选做2的任何功能，否则会导致程序错误**。

### 1. 必须严格遵守的不变基础假设
| 假设编号 | 核心规则 | 不可修改要点 |
|----------|----------|--------------|
| 假设1 | 整型(int)与浮点型(float)变量禁止相互赋值、相互运算 | 完全禁止两类类型的混用，任何场景下都不允许隐式/显式的跨类型赋值与运算 |
| 假设2 | 仅int类型可参与逻辑运算、作为if/while语句的条件；仅int和float类型可参与算术运算 | 结构体、数组类型禁止参与算术/逻辑运算，非int类型禁止作为分支/循环条件 |
| 假设3 | 函数仅能定义一次，不支持函数声明 | 禁止实现函数声明相关功能，禁止新增函数声明的产生式与错误检查 |
| 假设4 | 所有变量（含函数形参）作用域为全局，程序中所有变量均不可重名 | 禁止实现多层嵌套作用域，无需处理内层/外层同名变量的遮蔽逻辑 |
| 假设6 | 函数无法进行嵌套定义 | 禁止处理函数内嵌套定义函数的场景 |
| 假设7 | 结构体中的域不与变量重名，不同结构体中的域互不重名 | 无需处理结构体域名与变量名、跨结构体域名的重名冲突检查 |

### 2. 选做3.3专属修改的核心规则（唯一可改动项）
1.  **核心变更**：将结构体间的类型等价机制，由**名等价(Name Equivalence)**改为**结构等价(Structural Equivalence)**。
2.  **结构等价判定规则（强制要点）**
    - 两个结构体类型等价的判定标准：**成员数量完全相同、对应位置的成员类型完全等价、成员声明顺序完全一致**，与结构体名称无关。
    - 递归判定：结构体嵌套时，嵌套的子结构体也需按上述结构等价规则递归校验。
    - 数组例外规则：数组类型不展开判定，仅对比数组的**基类型和维数**，不对比数组大小。
    - 匿名结构体规则：每个匿名结构体视为具有独有隐藏名，仍按结构等价规则判定。
3.  **正反例约束**
    - 合法等价示例：`struct a {int x; float y;}` 与 `struct b {int y; float z;}` 判定为等价类型。
    - 非法不等价示例：`struct A {int a; struct {float f; int i;} b[10];}` 与 `struct B {struct {int i; float f;} b[10]; int b;}` 判定为不等价类型。
4.  **赋值语义适配**：结构等价的结构体变量可直接相互赋值，语义为对应域逐域赋值（含数组域），不触发类型不匹配错误。

## 二、必须完成的17类语义错误检查
> 要点：所有错误类型必须完整实现，其中**错误类型5、9需适配结构等价规则调整判定逻辑**，其余错误类型按原规则实现。

| 错误类型编号 | 错误触发场景 | 选做3适配要点 |
|--------------|--------------|----------------|
| 1 | 变量在使用时未经定义 | 规则不变，按全局作用域检查 |
| 2 | 函数在调用时未经定义 | 规则不变 |
| 3 | 变量重复定义，或变量与已定义结构体名重复 | 规则不变，全局作用域下变量名、结构体名全局唯一 |
| 4 | 函数重复定义（同名函数多次定义） | 规则不变 |
| 5 | 赋值号两边的表达式类型不匹配 | **核心适配**：结构体变量赋值时，按结构等价规则判定类型是否匹配，等价则合法，不等价才触发该错误；int/float/数组类型匹配规则不变 |
| 6 | 赋值号左边出现只有右值的表达式 | 规则不变，仅ID、数组访问、结构体访问可作为左值 |
| 7 | 操作数类型不匹配/操作数类型与操作符不匹配 | 规则不变，结构体/数组禁止参与算术运算，int与float禁止混合运算 |
| 8 | return语句的返回类型与函数定义的返回类型不匹配 | 规则不变 |
| 9 | 函数调用时实参与形参的数目或类型不匹配 | **核心适配**：形参/实参为结构体类型时，按结构等价规则判定类型是否匹配 |
| 10 | 对非数组型变量使用`[]`数组访问操作符 | 规则不变 |
| 11 | 对普通变量使用`()`函数调用操作符 | 规则不变 |
| 12 | 数组访问操作符`[]`中出现非整数 | 规则不变 |
| 13 | 对非结构体型变量使用`.`操作符 | 规则不变 |
| 14 | 访问结构体中未定义的域 | 规则不变 |
| 15 | 同一结构体中域名重复定义，或结构体域定义时进行初始化 | 规则不变 |
| 16 | 结构体名与已定义的结构体/变量名重复 | 规则不变，全局作用域下结构体名全局唯一 |
| 17 | 使用未定义的结构体定义变量 | 规则不变 |

### 错误检查强制要求
1.  发现单个语义错误后，**禁止立即退出程序**，必须扫描全文件检出所有错误。
2.  单个错误引发的连锁类型错误，建议全部上报，核心错误必须准确上报。
3.  禁止漏报、错报，无错误的输入文件必须无任何输出。

## 三、输入输出格式强制要求
### 1. 输入格式
- 程序接收**单个输入文件名**作为命令行参数，示例：`./cc test1`。
- 输入为包含C--源代码的文本文件，每行最多1个错误，可包含多个语义错误。
- 可安全假设输入无注释、八进制/十六进制数、指数形式浮点数，无词法/语法错误。

### 2. 输出格式
- 无语义错误的输入：**无任何标准输出**。
- 存在语义错误的输入，必须严格按以下格式输出每一条错误：
  ```
  Error type [错误类型编号] at Line [出错行号]: [错误说明文字].
  ```
- 强制要点：**错误类型编号、出错行号必须100%准确**，错误说明文字无强制内容要求，需匹配对应错误场景。

## 六、关键实现提示
1.  **类型系统实现**
    - 必须用结构体+链表实现类型表示，支持基本类型、数组类型、结构体类型，结构体域用链表串联。
    - 结构等价判定必须递归实现，逐节点对比结构体域链表的数量、顺序、对应类型。
2.  **符号表实现**
    - 按全局作用域实现单张符号表即可，无需实现作用域栈/多层作用域。
    - 符号表必须记录：变量名+类型、函数名+返回类型+形参个数+各形参类型、结构体名+结构体类型定义。
3.  **语义分析实现**
    - 推荐Bison仅用于构建语法树，语义分析代码单独写在独立文件中；若在Bison中插入语义动作，仅使用综合属性。
    - 遇到定义节点（ExtDef/Def），提取信息插入符号表；遇到表达式节点（Exp），查表完成类型检查。
    - 左值错误仅从语法层面检查：赋值号左侧仅允许ID、数组访问、结构体访问，其余形式直接触发错误类型6。
