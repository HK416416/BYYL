# 实验报告 — 语义分析器实现与调试

## 一、实验目标与概述
本实验目标是实现一个基于AST遍历的C--语言语义分析器，在实验一得到的抽象语法树基础上，完成符号表构建、类型检查与17类语义错误的检测与报告。要求支持结构体类型的结构等价判定（选做3.3），并在发现错误后继续扫描以检出全部错误，满足自动化评测系统的精确比对要求。

本次实现主要修改与维护的核心文件包括：semantic.h（语义分析接口）、semantic.c（语义分析主逻辑）、symbol.h/c（符号表实现）、type.h/c（类型系统与结构等价判定）、main.c（集成语义分析入口）。
## 二、总体设计与数据结构

- 类型系统：采用结构化的类型表示，支持基本类型（int/float）、数组类型（元素类型+大小）、结构体类型（域链表）。域链表记录域名、类型及定义行号，用于结构体成员的查找与等价比较。

- 符号表：按全局作用域实现单张哈希表。符号种类包括变量、函数、结构体，分别记录变量类型、函数返回类型及参数列表、结构体类型定义。

- 语义分析上下文：维护全局符号表、当前函数返回类型、错误计数等信息，在遍历AST过程中传递。

- 表达式类型信息：记录表达式的类型及左值属性，用于赋值检查、运算类型检查等场景。

## 三、语义分析核心实现

3.1 结构等价判定（选做3.3）

在type.c中实现结构等价判定函数，核心逻辑如下：
基本类型：直接比较枚举值是否相等

数组类型：仅递归比较元素类型，不比较数组大小（符合PDF数组例外规则）

结构体类型：遍历域链表，逐对比较域名和递归比较域类型，要求域数量、顺序、递归类型完全一致

该判定忽略结构体名称，使`struct a {int x1; float y1;}`与`struct b {int x2; float y2;}`被判定为等价类型。嵌套结构体通过递归调用自动处理。

3.2 符号表构建

遍历AST时在以下节点插入符号：
- `ExtDef`（变量定义）：插入变量符号，检查重复定义（错误类型3）
- `ExtDef`（函数定义）：插入函数符号，检查重复定义（错误类型4），同时将参数作为变量插入符号表
- `StructSpecifier`（结构体定义）：插入结构体符号，检查名称重复（错误类型16）

3.3 17类语义错误检查

语义错误检查集成在AST遍历过程中，主要实现方式：

| 错误类型 | 检查场景 | 实现方式 |
|----------|----------|----------|
| 1,2 | 变量/函数未定义 | `analyze_exp`中查找符号表 |
| 3,4,16 | 重复定义 | 插入符号前查重 |
| 5,7,8,9 | 类型不匹配 | 调用`is_type_compatible`判定 |
| 6 | 左值错误 | 检查表达式`is_lvalue`属性 |
| 10,11,12,13,14 | 操作符误用 | 检查表达式基类型 |
| 15 | 域名重复 | 临时符号表记录已定义域 |
| 17 | 未定义结构体 | 查找结构体符号 |

错误恢复：发现错误后继续遍历AST，`has_error`标志记录是否发生错误。

## 四、遇到的主要困难与解决方案

1.结构等价的递归判定

- 困难：嵌套结构体需要递归比较，数组大小的比较规则与实验要求（不比较大小）存在差异。
- 解决：实现递归版本的类型比较函数，数组分支仅递归比较元素类型；结构体分支逐域递归比较。

2.错误行号的精确定位

- 困难：部分错误需报告变量名所在行而非整个表达式行号。
- 解决：递归向下遍历AST定位到ID终结符节点，获取其line字段。

3.结构体域名重复检查

- 困难：结构体定义中需检测同名域。
- 解决：在解析结构体定义时创建临时符号表，每添加一个域前先查重。
