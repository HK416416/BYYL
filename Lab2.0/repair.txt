2.2026年4月14日20:09
对于右值未定义，报错缺失
int main()
{
    int i = 0;
    i = k + 1;  
}
    在 semantic.c 的 analyze_exp 中，原先处理二元表达式的逻辑被一个与赋值判断相同的 if/else-if 
条件覆盖，导致当 AST 节点形式为 Exp OP Exp（例如 k + 1）时，赋值分支的外层条件为真但内部检测
到的不是赋值操作，因此不会进入二元运算处理分支，进而跳过对子表达式（如 ID k）的递归检查，导
致未报 undefined 变量错误。
修复内容：在 analyze_exp 中重构该段逻辑：
先取出 op 节点并判断是否为 ASSIGNOP（赋值），走赋值分支；
否则如果 op 节点为终结符，再判断是否为算术/关系/逻辑等二元操作并做相应类型检查；
这样可以保证递归调用 analyze_exp 去检查子表达式（包括 rvalue 中的 ID）并触发未定义符号错误。

对err03
int main() {
  foo();
  return 0;
}
增加对未定义函数的判断文件，修改：semantic.c（更新了 analyze_exp）
新增对两种函数调用形式的处理：
ID LP RP（无参调用）
ID LP Args RP（带参数调用）
行为：
在符号表中查找函数名；
如果找不到，报告 ERROR_UNDEFINED_FUNCTION（Error type 2）；
如果找到但不是函数，报告 ERROR_NON_FUNCTION_CALL（Error type 11）；
若是函数且带参数，则对每个实参递归调用 analyze_exp 并按顺序与函数的形参比较类型；形参数量或类型不匹配时，报告 ERROR_FUNCTION_ARGUMENT_MISMATCH（Error type 9）；
将表达式类型设为函数返回类型（以便上层类型检查）
